# 販売実績・分析ダッシュボード（2026年上期 1〜6月）

Barefoot Inc. の店舗別・商品/ブランド別・決済別の売上金額・点数を集計したダッシュボードです。

## 構成

- `dashboard.html` / `index.html` — 完成したダッシュボード本体（自己完結HTML、ブラウザで直接開けます。同一内容で2ファイル。`index.html`はVercel等の静的ホスティングでルートパスが解決されるように用意）
- `data/dashboard_data.json` — ダッシュボードが読み込む集計済みデータ（`dashboard.html` に埋め込み済み）
- `scripts/etl.py` — 17件の生データファイル（Excel/CSV）を正規化して `data/records.json` を生成するETLスクリプト
- `scripts/aggregate.py` — `records.json` を店舗別・ブランド別・月次などに集計し `data/dashboard_data.json` を生成するスクリプト

> 生データ（Excel/CSVの元ファイル）は社外秘のためこのリポジトリには含めていません。
> `scripts/etl.py` はソースファイルパスを再設定すれば再実行できます。

## 画面構成

ヘッダー右上に **日本語 / English** 切替バー。**分析期間の指定は独立したバーを持たず、各セクションの見出しにあるプルダウンで個別に選択**します（同じ画面内でもセクションごとに異なる期間を見比べられます）。「全体サマリー」と「VFFシューズ」の総足数・総売上金額は、半期・Q1・Q2を常時並べて表示し、月次のみプルダウン（または表）で選ぶ設計です。月次推移など「期間そのものがテーマ」のグラフは常に1〜6月の6ヶ月分を表示し、グラフ下の「実績詳細を表示」ボタンで月別の数値を表で確認できます。

ダッシュボードは5つのタブで構成:

- **全体** — ①**全体サマリー**: 総売上金額・総点数・客数（伝票数）を、それぞれチャネル区分別内訳の円グラフとYoYバッジ（前年データ未取得のため準備中表示）付きで、半期・Q1・Q2（常時表示）＋月次（プルダウン選択）の4期間で表示／②**月次推移**: チャネル別積み上げ棒グラフ（金額/点数トグル、「実績詳細を表示」で月別数値表）／③**チャネル別 ブランド構成**: プルダウンでチャネルを選ぶと、そのチャネル内のブランド構成比を円グラフで表示
- **VFFシューズ** — ①**総足数・総売上金額**: 1〜6月とQ1・Q2・半期を常時、表形式で表示／②**月次販売足数推移（店舗別積み上げ棒グラフ）**: 主要7店舗を個別色分け+その他店舗をまとめた「その他」（「実績詳細を表示」で月別数値表）／③販売チャネルシェア（足数/金額トグル、ドーナツ⇄テーブル連動ハイライト）／④性別セグメント分布（推定）／⑤モデル別販売ランキング（「実績詳細を表示」で月別数値表）
- **店舗別** — ①**店舗・チャネル別 売上テーブル**（全店舗を一覧表示、列見出しクリックでソート可能）／②決済方法別比率（全体）／③店舗ごとの詳細（プルダウンで1店舗を選び、月次推移・ブランド構成比・決済方法比率を深掘り表示）
- **商品・ブランド別** — ①**ブランド別売上構成（全体）**: プルダウンで金額/数量を切替できる円グラフ⇄テーブル連動表示／②全ブランド合算モデル別Top10/Worst10ランキング／③ブランド別売上詳細（ドロップダウン、16件超は「もっと見る」で展開）／④Others内訳
- **このデータについて** — 訂正履歴、未対応データ、集計ルール（店舗・チャネル7区分の定義、各セクションの表示ルールなど）、ソースファイル一覧

## 分析期間・多言語対応

- **セクション別期間指定**: `scripts/aggregate.py` が全ての集計次元（店舗別・ブランド別・モデル別・チャネル別・VFFシューズ関連など）を月次（2026-01〜06）で `data/dashboard_data.json` に出力し、各セクションが自分専用の期間状態を持ってクライアント側で合算・再描画します。グローバルな期間バーは持たず、セクションごとに独立して選択可能です。
- **日英切替**: ヘッダーの「日本語 / English」ボタンで、タブ名・KPIラベル・セクション見出し・表ヘッダー・ツールチップ・「このデータについて」タブの全文まで切り替わります。店舗名・ブランド名などデータ由来のラベルも主要なものは英訳付き。選択言語は `localStorage` に保存され再訪問時も保持されます。

## 店舗・チャネルの7区分

「全体」「店舗別」「VFFシューズ」の全タブで共通の分類（`scripts/aggregate.py` の `STORE_GROUP`）:

| 区分 | 対象店舗 |
|---|---|
| 直営実店舗 | K Village、Paradise Park |
| Central百貨店内 | Central Chidlom、Central Chidlom Online、Central World (CDS)、Central Lardprao (Dept.)、Central Eastville、Central Ladprao 3F (Coollabo)、VFF Cart LP |
| オンライン | Online |
| イベント | Event |
| 委託販売 | BFT Consignment、EDV Consignment |
| Siam Discovery | Siam Discovery（独立区分） |
| Thaniya | Thaniya（独立区分。VFFシューズは扱っていないためVFFシューズタブのチャネル別内訳には登場しません） |

以前は「実店舗」という1つの広い区分にK Village/Thaniya/Paradise Park/Coollabo/VFF Cart LP/Siam Discoveryをまとめていましたが、直営店・百貨店内・独立店舗の実態に合わせて7区分に再編しました。VFFシューズタブの販売チャネルシェアも、この共通区分から動的に算出しています（`vff_shoes.store_monthly` の店舗別データを `stores[].group` でロールアップ）。

## 可視化の設計

- **チャネル別 積み上げ棒グラフ**（全体 02）— 月次推移を7区分で色分けした単一軸の積み上げ棒グラフ（金額/点数トグルで切替、二軸グラフは可読性の観点で不採用）。グラフ下の「実績詳細を表示」でチャネル×月の数値表を展開
- **チャネル別ブランド構成**（全体 03）— チャネルをプルダウンで選択すると、そのチャネル内でのブランド構成比を円グラフで表示
- **VFFシューズ 月次店舗別グラフ** — 主要7店舗（H1合計の販売足数が多い順）を個別色分けし、それ以外は「その他」にまとめた積み上げ棒グラフ。13店舗全てを別々の色にすると識別できなくなるため、上位7+その他に集約（`scripts/aggregate.py` に `vff_shoes.store_monthly` を追加）。グラフ下の「実績詳細を表示」で店舗×月の数値表を展開
- **全体サマリー・VFFシューズ総足数のYoYバッジ／表形式表示** — 期間ドロップダウンではなく、半期・Q1・Q2を常時並べて表示（比較しやすさを優先）。前年データが届き次第、YoYバッジが自動的に点灯する設計
- **ドーナツグラフ ⇄ テーブルの連動ハイライト** — 「ブランド別売上構成」（商品・ブランド別）と「VFFシューズ チャネル別内訳」で、ドーナツのセグメントとテーブルの行を相互ホバーでハイライト連動
- **店舗・チャネル別売上テーブルのソート機能**（店舗別タブ）— 列見出しクリックで昇順/降順ソート
- **モデル一覧の「もっと見る」展開**（商品・ブランド別タブ）— ブランド別詳細テーブルは上位15件のみ初期表示、残りは「もっと見る」ボタンで展開（Othersブランドは112モデルあり効果大）
- **KPI数値の強調** — 数値フォントサイズを拡大（28px→38px）
- **チャネル配色の統一** — 7区分に固定の配色（青・橙・緑・黄・マゼンタ・深緑・紫）を新設し、積み上げグラフ・チャネル別ブランド構成・店舗別テーブル・VFFシューズ販売チャネルシェアの全てで同一チャネルは常に同じ色になるよう統一。VFFシューズ店舗別グラフの店舗配色も別途固定。配色はdataviz skillの`validate_palette.js`でダーク画面上の色覚多様性対応（CVD分離度・明度帯・コントラスト比）を検証済み

# スケジュール & 積み上げ管理アプリ (`schedule.html`)

予定・タスクと、ランニング／筋トレ／語学学習などの「自分の積み上げ」を1画面で管理する個人用アプリです。
サーバーもログインも不要で、`schedule.html` をブラウザで直接開くだけで動きます（静的ホスティングに置いた場合は `/schedule.html`）。

## データの持ち方

- 保存先はブラウザの **localStorage**（キー: `plog.v1`）。外部に送信されるデータは一切ありません。
- **ブラウザの閲覧データを消すと一緒に消えます。** 設定タブから **JSONの書き出し／読み込み** ができるので、定期的なバックアップと端末移行はこれで行います。
- 同じブラウザ・同じドメインで開く限りデータは保持されます（`file://` で開いた場合と、ホスティング上で開いた場合は別のデータ領域になります）。

## 画面構成

5つのタブで構成しています。

- **今日** — KPIタイル（今日の予定数／未完了タスク／連続記録日数／通算記録日数）、種目ワンクリックの記録入力、今日の予定タイムライン、タスク（期限切れ・今日・期限なし＋この先の件数）、目標の達成状況
- **カレンダー** — 月表示グリッド。各日に予定チップ・タスク件数バッジ・記録ドット（種目色）を表示。日付をクリックすると、その日の予定・タスク・記録を並べた詳細パネルが下に出て、その場で追加・編集できます
- **記録** — 種目の管理（名前・単位・色・目標）と、記録履歴の一覧（種目フィルター、50件ずつの「もっと見る」）
- **積み上げ** — 継続ヒートマップ、週次の推移、累積の積み上げ、目標の達成率。上部のチップで「すべて／種目別」を切り替えると全セクションが連動します
- **設定** — 週の開始曜日、JSONバックアップ、サンプルデータ投入、全削除

## データモデル

```
activities  種目   { name, unit, colorIdx, target: { period: day|week|month, value } }
logs        記録   { activityId, date, value, memo }
events      予定   { title, date, allDay, start, end, place, memo, cat }
tasks       タスク  { title, due, pri, memo, done, doneAt }
```

記録は「日付 × 種目」で合算されます。同じ日に同じ種目を複数回入れた分は合計として扱われます。

## 可視化の設計

- **継続ヒートマップ** — 直近53週。種目を選ぶとその種目の記録値の大きさ、「すべて」ではその日に記録した種目数を濃淡で表現します。しきい値は外れ値で潰れないよう非ゼロ値の90パーセンタイルを基準にしています。マスをクリックするとカレンダーのその日に飛びます
- **1軸の原則** — 種目ごとに単位（km／分／ページ…）が違うため、複数種目を1つのグラフに重ねず、**種目別の小さなグラフ（スモールマルチプル）** に分けています。二軸グラフは使っていません
- **配色** — 種目の識別色は固定順で割り当てるカテゴリカルパレット。dataviz skill の `validate_palette.js` でダーク面（`#16241C`）に対して検証済みで、明度帯・彩度下限・隣接ペアのCVD分離度（色覚多様性）・通常視の分離度・コントラスト比のすべてでPASSしています。ヒートマップは単一色相のアンバー系ランプ（OKLab明度 0.358 → 0.494 → 0.634 → 0.765 の単調増加）
- 全グラフにホバーツールチップと、`データを表で見る` の表ビューを用意しています

## 既知の制約

- リマインダー通知と繰り返し予定は未対応です
- 複数端末間の自動同期はありません（JSONの書き出し／読み込みで移行してください）
